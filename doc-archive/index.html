      How it scales on your platform

      PlanThis section is the build plan for a production platform. Nothing in it was run or measured in this demo.

      1. Batch queueUploads land in S3 and every page becomes a task on a queue (SQS). Workers take tasks in parallel, retry failures and report progress per batch, so a large job runs as many small tasks instead of one long one.
      2. Production OCRAmazon Textract reads printed text and handwriting and returns a confidence score for each word. Pages with low confidence go to a review list instead of being trusted as they are.
      3. Models on BedrockFolder suggestions, summaries and answers run on Amazon Bedrock models inside your AWS account. Each AI result is stored with its page, so a re-run skips work that is already done.
      4. Cited searchPage text and embeddings go into one search index (keyword plus vector). Answers quote the page they come from, and say so when no page supports an answer.
      5. Duplicates at volumeExact copies are caught by hashing. Near copies are compared by text fingerprints, only inside groups of likely matches, so the check stays fast as the archive grows.
      6. Configurable verticalsDocument types, fields and folder rules live in a configuration per vertical, so a new vertical is a configuration change, not new code.
      7. Later phasesDocument markup and forms; a secure API and an MCP server on top of the same search, with access control per customer; subscription billing with Stripe.
