DeepL glossary from public EN/FR product pages: terms, keep-as-is names, clashes

English product records and their existing French versions go in. Out come term pairs with how often the French really follows them, the names that stay in English, the terms translated two or more ways, and a CSV that DeepL accepts as a glossary.

Status (2026-11-06 16:41 UTC): built from one art-materials brand's public UK (English) and French online stores. The product pages refused automated requests (HTTP 429, rate limit), so I did not collect product descriptions. I used the stores' public sitemaps instead, which carry each product's title and image alt text in both languages. Products were paired when both stores use the same image file: 1,274 pairs, 1,224 of them with alt text.

Run: term choice by Claude on a 50-product sample; every count, confidence and clash below measured by a script on 1,014 build products; checks on 260 held-out products. Not run: DeepL itself (no API key), so the with/without-glossary scores are a design, not results.

DESIGNED, NOT RUN DeepL with vs without the glossary

  1. Translate the held-out English twice with the DeepL API: no glossary, then with the glossary from the CSV.
  2. Expected-term hit rate: share of glossary terms whose French target appears in each output.
  3. chrF of each output against the existing human French (character-level, fair to small inflection changes).
  4. Semantic similarity (multilingual sentence embeddings, cosine) so a valid rewording is not scored as wrong.
  5. Per rule: products where the glossary run scores better or worse, so bad rules show up by name.
  6. A random sample goes to a French reviewer; their verdicts tune the rules.

6. Downloads

DeepL glossary CSV (70 pairs) Master glossary JSON 50-product sample (EN/FR) All 1,274 pairs with URLs

CSV format: one source,target pair per line, UTF-8, no header, fields with a comma or quote in double quotes, no duplicate sources, as in DeepL's glossary entry formats. Left out of the CSV on purpose: single colour adjectives (French gender and word order change, e.g. Laque Orange Foncée), context terms such as Hue, Shade and Medium, and pairs under 90% confidence or seen in fewer than 3 products. Each one says why in the JSON.

7. Method

  1. Read both stores' public product sitemaps (robots.txt allows it) and pair products by shared image file.
  2. Claude read 50 aligned pairs from 11 product families and wrote down the candidate terms and every French rendering seen.
  3. A script checked each candidate on all build products: longer terms first (Cobalt Blue before Blue), then counts, confidence and clashes.
  4. Rules for the DeepL CSV are applied, then the held-out products are checked.

Limits: titles and alt text only, no long descriptions (blocked); one language pair; pairing by shared image can link two different products (one case shown in section 4); confidence is agreement with the existing French, not proof that it is right.
