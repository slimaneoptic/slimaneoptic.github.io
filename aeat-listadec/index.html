What AEAT's guide adds

  • Each call returns at most 1000 keys, the oldest first, in ascending order of creation date (section 4.1).
  • Each clave is then used with the second service, DetalleV5SOAP, to download that message (section 4.2).
  • The declarant can be someone other than the signer, under a power of representation (apoderamiento). Asking for a type you are not authorised for returns an error (sections 4.1 and 7).
  • SOAP 1.1, document/literal; errors come back as a SOAP Fault (sections 2 and 6.3).

4. Diagnostics a test run must name

  
Fact = read in AEAT's WSDL, XSD or guide, or checked on 2026-11-02. Expected = general SOAP/TLS behaviour, not seen on AEAT yet.

  
FailureWhat is knownHow the test interface detects it

    
No client certificate / TLS handshake refused
        Fact The three internet hosts all ask for a client certificate in the TLS 1.2 handshake. www1 (production) and prewww1 (pre-production) list the same 100 accepted CAs, among them FNMT-RCM "AC Representación" and Camerfirma; www10 (seal certificate) lists 55. Checked with openssl s_client; no request was sent.
Expected Without a certificate: a handshake error or an HTML error page, not SOAP.		
        Connection-level error before any HTTP status (the cURL error number in PHP), or a body that is not XML. Log the certificate subject, issuer and expiry before each call.

    
Certificate expired or from an unlisted CA
        Expected The handshake fails the same way.
        Before calling: check the validity dates, and that the issuer is in the CA list the server sends during the handshake.

    
Wrong endpoint
        Fact The WSDL lists 5 addresses; the 2 intranet hosts do not resolve in public DNS. prewww1.aeat.es is pre-production.
Expected Production messages are not visible in pre-production, so a test run there can return an empty list.		
        The configured URL must equal one of the WSDL port addresses. Then DNS error vs HTTP 404 vs non-XML body, each named separately. The test page shows which environment it called.

    
Schema error in the request
        Fact See section 3: lxml names the exact element or attribute.
        Validate the Body against ListaDecV4Ent.xsd before sending, and refuse to send on error.

    
SOAP Fault from AEAT
        Fact Guide 6.3: faultcode soapenv:Server means resend; soapenv:Client means the request is formally wrong or reuses a reference with different content, so do not resend.
Expected AEAT's own error code sits in faultstring or detail; the files do not define its format.		
        Parse Body/Fault, show faultcode, faultstring and detail verbatim, and mark it "retry" or "do not retry" from the faultcode.

    
No answer, or not the expected XML
        Fact Guide 6.3: if the transmission does not complete or the reply is not the expected XML, resend.
        Timeout, unparseable body, or a body that fails ListaDecV4Sal.xsd.

    
Empty list
        Fact A ListaDecV4Sal with zero declaracion is valid (minOccurs=0): nothing pending, not an error.
        After the schema check, count = 0 shows "no pending messages", in a different colour from errors.

    
List cut at 1000
        Fact Guide 4.1: at most 1000 keys per call, oldest first.
        Count = 1000 shows "more may be waiting: read these, then call again".

    
Not authorised for this declarant or type
        Fact Guide 7: filtering by a type you are not authorised for returns an error.
Expected It arrives as a SOAP Fault.		
        Show the certificate holder next to NifDeclarante so a representation problem is visible at once.
