    Guardrails and the 20-question test

    1. Only from the graph, with a citationThe question runs a read-only typed search of the graph. The model sees only the retrieved records and must cite the ids it used. The code then checks every citation: it must be in the retrieved set, and its quote must exist in the source file.
    2. No support, no answerIf nothing is retrieved, if the model finds no supporting record, or if a citation check fails, the answer is "I don't know: not in the project records." Nothing is guessed.
    3. Unsure links go to a personWhen the graph is filled, every node and link is checked against the fixed ontology. Unknown types are rejected. Low-confidence links, quotes not found in the source, and links that conflict with the logs are held in a review queue instead of entering the graph.

    The two-week first version

    One project, one data source, two weeks. The plan this demo follows. Names of types and links adapt to your working model; the shape stays.

    1. Days 1-3

      Agree the model

      • Start from your working model. Fix 8-10 types and about 10 links (this demo: 10 types, 13 link types).
      • Collect 20 real questions your users ask, with the right answers. This is the test set.
    2. Days 4-9

      Fill the graph from one source

      • First source: the submittal and RFI logs of one project (an export from Procore or ACC) plus the documents they point to.
      • The model reads each document into the fixed types. Every fact keeps its source. Unsure links go to the review queue.
    3. Days 10-14

      Answer with guardrails

      • Question → read-only graph search → answer that cites the record and the document. No support → "I don't know".
      • The Monday brief. The 20 tests run after every change; you see the score and the misses.

    What this demo is. A synthetic project of 25 submittals, 15 RFIs, 6 change orders, 30 schedule activities and 12 short documents, generated with a fixed seed, with planted problems: a superseded drawing revision, a late submittal that blocks an activity, an RFI that changed a drawing and caused a change order, a decision that exists only in meeting minutes, and questions the records cannot answer. The whole run (filling the graph and two test runs) cost $0.24 in model calls; filling the graph took 87 seconds.

    What it is not. Not a real project and not a construction client's data. The log rows here are clean; real exports need column mapping and duplicate handling. Documents are short text; real PDFs need OCR and page splitting. The question search is keyword and type based; a larger project needs an embedding index too. The graph lives in memory, not in a graph database. No user accounts or permissions yet.

    • Built and run: ontology, extraction with validation and review queue, graph, guardrailed answers, 20-question test, Monday brief.
    • Known limits: keyword retrieval, in-memory graph, synthetic clean inputs, one project only.
    • Not built: Procore or ACC connection, nightly sync, Teams or Slack bot, email delivery, permissions.

    Synthetic data. Every company, person, project, document and number on this page is invented for the demo (fixed seed, generated 03 Oct 2026, records as of 03 Oct 2026). No real construction project or client data was used. Answers were produced by the pipeline on 03 Oct 2026 and replayed here.
